# 管理员归属与功能授权

入口：**系统设置 → 管理员管理 → 功能授权**。

- `tjt740` 为一级管理员，可创建二级或三级账号，查看全部账号和归属关系。级别和身份绑定账号 ID，不依靠登录会话中的用户名判断。
- `lhm`、`pink` 为内置二级管理员，恢复并保留原有功能权限及已保存的邮箱范围，可创建直属三级账号。两者不参与普通子账号的逐项功能授权，不可被删除或由其他账号重置密码；可以自行修改密码。一级仍可配置其原有邮箱范围。
- 新增管理员可选择“管理员级别”和“归属上级（可选）”。一级创建二级时只能归属自己，创建三级时可归属自己或某个二级管理员；二级只能创建归属自己的三级账号。归属留空默认使用创建人。
- 三级为末级，不能继续创建或管理下级。后端同时校验级别、创建权限和归属，不能通过伪造请求创建一级、平级或第四级账号。
- 新建的二级和三级账号默认没有功能权限，可以登录账号设置修改自己的密码。上级需逐项授权：首页、邮箱、跨账号全部邮箱、代理池、卡密、卡密日志、收件日志、系统配置、本人万能密钥；二级还可获授下级管理和邮箱范围授权权限。账号不能获得超过所选上级的有效权限。
- 上级只能授予自己拥有的权限；下级有效权限同时受所有祖先权限限制。最高管理员为更深层账号授权时，需要先确保其上级已获得相应权限，避免出现保存成功却不能使用的情况。
- 首页统计、代理池、卡密和系统配置涉及全站共享数据。邮箱和收件日志按邮箱范围过滤；“查看全部邮箱（跨账号）”需要单独授权。
- 所有页面、旧版页面及后台 API 都在服务器检查权限。菜单隐藏只是交互提示；直接请求 API 仍会校验。撤权在下一次请求立即生效，菜单刷新后更新。

## 邮箱范围

普通管理员默认可访问本人创建的邮箱，以及上级明确授权的邮箱或分组。分组授权包含后续加入的邮箱；继续向下授权时，只能选择自己当前可访问的邮箱或本人可管理的分组。上级失去某邮箱的访问权后，经由该上级传递的授权立即受限。

账号归属独立于旧版 `admin_mailbox_scopes` 的范围配置，修改邮箱范围不会抢走账号归属。不能通过关闭“限制”开关自行获取全站邮箱权限。

## 密钥与账号保护

- 最高管理员设置全站万能密钥；普通管理员设置本人密钥，不能改写全站密钥。密钥仅保存哈希，不回显明文。
- 本人密钥的使用要求同时具备“本人万能密钥”和“邮箱管理”权限，并校验实际邮箱范围。不同管理员不能设置相同的密钥。
- 撤销本人密钥权限会清除该账号及下级的旧密钥；重新授权后需要重新设置。重置或修改密码也会清除该账号的个人密钥，并使旧会话失效。删除账号后旧会话立即失效。
- 管理员用户名作为旧版邮箱归属字段使用，因此界面禁止改名，避免冒领或丢失数据归属；密码仍可修改。
- 内置管理员和当前账号不能被删除。有直属下级的账号必须先处理下级，不能级联误删。删除末级账号时，其邮箱和分组转归直属上级，相关授权记录清理；这也防止重新注册同名账号冒领遗留数据。

原有匿名邮箱地址取件和公开卡密取件流程继续保留。后台权限与本人密钥范围不改变公开取件入口的业务规则。

## 升级

程序启动时自动创建或升级 `admin_access` 权限表，保存 `admin_level` 和 `is_builtin_admin`。首次升级登记 `tjt740` 为一级、现有 `lhm` 和 `pink` 为内置二级；原有邮箱及分组授权、密码和会话版本保留。已有旧权限表也会进行一次级别迁移，修正曾将 lhm/pink 当作普通受限子账号的情况，其余账号的归属和授权保留。若全新安装尚无 `tjt740`，保留最早创建的账号为初始化一级管理员，避免默认安装无法进入后台。

迁移可重复执行，不会重置已经保存的归属和授权。请按正常数据库备份与发布流程升级；代码、`admin_security.py`、模板和 `static/react/` 构建资源需要一起更新。直接使用 Gunicorn 等方式导入应用的部署，应在启动工作进程前调用一次 `init_db()` 完成迁移。
